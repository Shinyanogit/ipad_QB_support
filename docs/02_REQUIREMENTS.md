# Requirements

## 必須（MVP）
- QB演習ページ（旧 `/Answer/...`、新 `/quiz?question_id=...`）で動作する注入UI
- 問題情報の抽出
  - 問題ID
  - 進捗（例: `演習中 60 / 95 問目`）
  - 選択肢数
  - 掲載頁
  - 問題タグ（first/compulsory など）
  - 添付画像（最大4MB/枚、data URL化）
- SPA遷移やDOM更新に追従
- 解答後の解説末尾に問題単位の振り返り欄を表示
  - 入力は500ms debounceとblur/問題切替時flushで自動保存
  - URLの `question_id` を主キーにし、問題文・選択肢・掲載頁・タグも将来のAnki生成用に保持
  - 既定PDFは `Vital_Step2CK` とし、PDFページ参照を後から追加できる形で保存
  - 画像はpaste（ClipboardEvent内File、HTML内`<img src>`、async Clipboard APIの順で取得）/ファイル選択/dropで添付できる
  - 添付画像はブラウザでPNGへ正規化し、本文とは別の `storage.local` キーへ保存する
  - 本文には `![[QB_[問題コード]_reflection_N.png]]` を保持し、再訪時にインライン画像へ復元する
  - 太字・斜体・下線・取り消し線は保存時にMarkdownへ直列化し、再訪時にcontenteditable内の書式へ復元する
  - B/I/U/Sの書式バー、および`Cmd/Ctrl+B`、`Cmd/Ctrl+I`、`Cmd/Ctrl+U`、`Cmd/Ctrl+Shift+S`で選択範囲の書式を切り替え、既存の自動保存経路へ反映する
  - 注入先サイトのCSSに打ち消されず、太字・斜体・下線・取り消し線が編集時に視認できる
  - 行頭`- `／`* `／`+ `を箇条書き、`1. `等を番号付きリストへ自動変換する
  - リスト内Enterで次項目を作り、空項目でEnterするとリストを終了するブラウザ標準contenteditable動作を維持する
  - リスト項目内のTab／Shift+Tabでインデント／アウトデントし、2スペース単位のネストMarkdownとして保存・復元する
  - ツールバーから箇条書き／番号付きリストを適用・種類変更・解除できる
  - 画像クリックで拡大し、背景クリック/閉じるボタン/Escapeで閉じられる
  - 画像または本文を保存できない場合は、ステータスと画面右下のalertで失敗を明示し、未保存の生`<img>`を残さない
- MM医師国試模試の復習ページでも振り返り欄を表示
  - 模試回と画面上の`A-1`形式の問題番号を組み合わせ、URLの`question_id`がSPA切替後も固定でも問題ごとに異なる保存IDを使う
  - 画面上の問題番号を取得できない間は振り返り欄を生成せず、URL IDへフォールバックしない
  - URLの`question_id`は模試内の問題番号ではないため、旧URLベース保存IDからの一般的な自動移行や所有推定には使わない
  - ユーザーが所有先を確認済みの旧データだけ、明示的に確定した現行IDを保持対象にできる
  - 元問題以外へ既に複製された旧本文・旧画像マーカーは、保存データを削除せず誤配属として表示対象から除外する
  - ユーザーが所有先と本文を確認済みの旧データは、旧レコードが後から変化しても確認済み本文断片・画像ストア名から誤配属を検出できる
  - 問題文・選択肢・進捗・模試タグも同じ保存レコードに含める
  - 未解答状態でも「解答を確認する」ナビの直前に表示する
  - ダークテーマでは問題だけでなく、`.bg`、`.commentary`、`.accBody`、`.yourAnswer`、解答履歴表も暗色背景と明色文字にする
  - 模試専用スタイルは `data-qb-site="moshi"` で限定し、通常QBへ波及させない
- ダークテーマの問題・解説内で`/exam_images_kokushi/`画像を含む`p > figure > img`は、透過領域内の黒い注釈が潰れないよう3要素すべて白背景に固定する
- 上記画像領域はcomputed styleによる明色surface暗色化の対象から除外する
- ダークテーマでは親コンテナのクラスに依存せず、`background-color:#EFEFEF`／同値の`rgb(239, 239, 239)`を持つ要素と子要素を暗色背景・明色文字へ統一する
- 設定保存（`storage`）
  - ショートカット有効/無効
  - ナビ（前/次）、解答、選択肢キーの割り当て
  - ノート/検索バーの表示/非表示
  - ノート非表示設定は基準値パネルへ影響させない
  - ChatGPTバーの開閉/位置/APIキー/モデル/手動キー使用のON-OFF
  - テーマ（ライト/ダーク/システム）とページ色差し込み
  - 設定は保存ボタン不要で自動反映（閉じたタイミングで保存）

## ChatGPTバー要件
現在は一時停止中。以下は再有効化時の要件として実装を保持する。

- 右側ドックで開閉でき、ドラッグで幅調整が可能（本文を押し出す）
- APIキーはユーザーが設定（保存済み表示、`sk-pro` 以外は無効）
- モデル選択（`gpt-5-mini` / `gpt-5.2` / `gpt-5.2-chat-latest` / `gpt-5` / `gpt-4.1` / `gpt-4o`）
- APIキー未設定時はバックエンド経由で `gpt-5-mini` / `gpt-4.1` を使用（切替可）
- 問題文＋選択肢＋画像を自動で取り込み、質問に回答
- ストリーミング表示・Markdown表示・コピー・トークン/概算費用表示
- 会話履歴を保持しつつ、`Ctrl+N` で新規会話にリセット
- ユーザー入力が400語超の場合は折りたたみ表示（クリックで開閉）

## キーボード操作（PC向け）
- `ArrowRight`/`ArrowLeft` で次/前の問題へ移動
- `a`〜`g` で選択肢(0-6)をトグル（設定で変更可）
- 「解答する／解答を確認する」キーは設定で変更可（初期値は `S`）。MM模試の復習画面では「リトライ」も同じ主操作として扱う
- 上記3系統はQBとMM模試の両方で動作する。MM模試では `.choice-cell`、`.btn-prev`、`.btn-next` とボタン文言から対象を解決する
- 英字ショートカットはIMEの `event.key` ではなく物理 `KeyboardEvent.code` もフォールバックに使う
- `Ctrl+O` でチャットドック開閉（Chat有効時）
- `Ctrl+S` でChat設定パネル開閉（Chat有効時）
- `Ctrl+N` で会話リセット（Chat有効時）
- 修飾キー付きショートカットは入力中でも有効（入力欄でのIME変換中は除外）
- MM模試の振り返り欄など、テキスト入力中は選択肢・解答・ナビの単独キーを発火させない

## iPad向けUI要件
- キーボード依存を避け、タップ操作のUIを用意
- トップ文書/iframe/SPAでDOMが変わっても再注入される

## 重要方針
- 参照HTMLのDOM構造に基づく安定セレクタとフォールバックを併用
- 中核ロジックは純粋TSとして切り出す
- UI/拡張API依存は最小化する
- 振り返り画像は1枚12MBを上限とし、PNGバイトSHA-256で問題内の重複添付を排除する
- Chrome版は画像用に `unlimitedStorage` を要求する。Safariで容量制限に達した場合も保存失敗を必ず表示する

## 非目標（現時点）
- 解説全文の保存
- 学習履歴の永続ログ
- 振り返りからのAnkiカード自動生成・AnkiConnect送信
